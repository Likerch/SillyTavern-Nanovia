## [0.7.0] — 2026-11-23

Медиа: картинки, видео, озвучка и распознавание речи NanoGPT через плагин.

### Плагин

- Каталоги четырёх видов медиа (картинки, видео, озвучка, распознавание) с ценами, параметрами и возможностями моделей,
  кэш на диске, обновление раз в час. Списки NanoGPT неоднородны (цены и параметры у каждой модели свои), поэтому
  плагин приводит их к единому виду и не доверяет ни одной форме.
- Маршруты `/media/image`, `/media/tts`, `/media/stt`, `/media/video` и файл готового видео с поддержкой `Range`.
  Видео-задачи хранятся на диске и переживают перезапуск; готовый файл плагин сохраняет у себя (у NanoGPT видео живёт
  около суток). Отмены задач у NanoGPT нет, удаление в Nanovia только забывает задачу.
- OpenAI-совместимые маршруты на порту прокси: `/c/<id>/v1/audio/speech`, `/audio/transcriptions`,
  `/images/generations` (по токену подключения), с заголовком `X-Nanovia-Cost` и записью в журнал расходов. Модель
  берётся из тела запроса.
- Тип звука берётся из ответа NanoGPT, а не из запроса: модель Kokoro отвечает WAV, даже если просили mp3.

### Стоимость

- Цена картинки в ответе NanoGPT совпадает с прайс-листом и может быть ниже списания (вживую: в ответе 0.0017, списано
  0.00255). Плагин записывает цифру из ответа, а через несколько секунд исправляет её по проверке биллинга запроса и
  дописывает в журнал строку-поправку. В панели видны оценка до вызова и реальное списание с пометкой источника.
- Озвучка считается по цене каталога (у неё нет ни id запроса, ни цены в ответе), распознавание берёт цену из ответа,
  видео показывает предоплату и итог. В журнале расходов у записей появились `medium`, `units`, `costSource`, в
  сводке расхода разбивка по видам запросов.

### Панель

- Вкладка «Медиа»: каталог всех четырёх видов, студии картинок, озвучки, распознавания (микрофон или файл) и видео.
  Поля формы строятся из параметров модели, оценка стоимости показывается до вызова.
- Провайдер «Nanovia» в расширении озвучки ST (`registerTtsProvider`), без токенов в настройках.
- `NANOVIA_API.media` для соседей: каталог, `generateImage`, `speak`, `transcribe`, `startVideo`, `videoStatus`.
- Вкладка «Аккаунт»: расход по видам запросов, в списке недавних запросов видны медиа-записи.

### Известное

- Видео проверено только на моке: форма ответов NanoGPT взята из документации (в ней два несовместимых описания статуса,
  плагин понимает оба). Картинки, озвучка и распознавание проверены вживую (`npm run test:live`).
- Не проверено на настоящем NanoGPT: учитывается ли `X-Billing-Mode: paygo` на медиа, одинаков ли коэффициент
  списания у разных моделей, асинхронные ответы озвучки, картинки по ссылке (`url`).
- В ST 1.19 нет клиента распознавания речи, поэтому микрофон встроен в панель Nanovia, а не в расширение ST.

## [0.6.0] — 2026-11-23

Первый выпуск. Этапы 0.1–0.6 собирались параллельными ветками и вышли вместе, поэтому отдельных тегов у этапов нет:
тег один, `v0.6.0`.

### Плагин и прокси (0.1)

- Серверный плагин `plugins/nanovia`: локальный OpenAI-совместимый прокси на `127.0.0.1:8787` (свой порт, потому что
  маршруты ST требуют сессию и CSRF) и админ-маршруты `/api/plugins/nanovia`.
- Подключение = именованный набор (модель, роутинг, рассуждения, биллинг, кэш, поиск, память, ключ). В Connection
  Manager оно видно как обычный профиль `Nanovia · <имя>`, поэтому его выбирает чат, Qvink и фоновые задачи соседей.
- Режимы `auto` / `plugin` / `direct`. Тихого переключения нет: плагин не отвечает, и это жёсткая ошибка с кнопкой
  «переключить на прямой режим».
- Токен прокси у каждого подключения свой: в секретах ST под `api_key_custom`, в реестре плагина только его sha256.
- Мок NanoGPT (`npm run mock`), локальный стенд без Docker (`npm run stand`), скрипты установки и деплоя.

### Роутинг, биллинг, рассуждения, ключи (0.2)

- Все поля `provider` в стиле OpenRouter: порядок, только/кроме, сортировка, квантизации, максимальная цена, ZDR,
  кэширующий маршрут, fallbacks, `require_parameters`.
- Биллинг: для каждой настройки видно, держит она запрос на подписке или переводит на оплату по факту (явный выбор
  провайдера даёт наценку около 5%). Режим «безопасно для подписки» убирает такие настройки из запроса.
- Политика рассуждений: «как в запросе» / фиксированный уровень / выключено. Фоновые задачи без подсказки считаются
  выключенными. Модели с фиксированным маршрутом получают только `zdr`.
- Несколько ключей NanoGPT с подписями, ключ выбирается на подключение. Значение ключа уходит в плагин один раз.
- Прямой режим: хук запросов в браузере собирает тот же запрос (`custom_include_body` / `custom_include_headers`).

### Каталог (0.3)

- Каталог моделей NanoGPT с ценами, контекстом, возможностями и пометкой «в подписке», фильтры и поиск, статистика
  хостов, подсказки по роутингу, выбор модели в форме подключения. Кэш на диске плагина и в IndexedDB браузера.

### Аккаунт, расход, стоимость (0.4)

- Баланс, квоты подписки, расход по дням и подключениям. Плагин просит у NanoGPT `usage` и переписывает ответ в стиле
  OpenRouter: `usage.cost` в долларах (0, если запрос покрыла подписка), `cached_tokens`, `reasoning_tokens`.
- Эквивалент по тарифу «оплата по факту» показывается отдельно и никогда не попадает в лимиты расходов.
- Журнал запросов плагина (JSONL), точная стоимость по `X-Request-ID`, список недавних запросов (`GET /usage/recent`),
  в который попадают и запросы через плагин, и запросы прямого режима.

### Публичный API и соседи (0.5)

- `NANOVIA_API`: `describeProfile`, `describeUrl`, `usage`, `account`, `advice`, `openPanel`, `doctor`, `mgmt`.
- Мосты: Maestro 1.35.0 (адаптер, карточка в пульте, рассуждения «выкл.» для фоновых профилей, подсказки в Preset
  Studio, проверка в Медике, эквивалент в Казначее), Dramatis 1.9.0, Localizer 0.7.0, Officina 0.10.0.

### Management API, поиск, память, диагностика (0.6)

- Management API NanoGPT (токен `sk-nano-mgmt-…`, только на стороне плагина): ключи с лимитами и модельные пресеты.
  Токен хранится в файле пользователя, не возвращается ни одним маршрутом и не попадает в логи.
- Веб-поиск (`:online`) и Context Memory (`:memory`, по умолчанию выключена) как настройки подключения.
- Вкладка «Диагностика»: проверки всей конфигурации с быстрыми исправлениями.

### Известное

- Management API NanoGPT помечен бетой; часть деталей (длина токена, коды ошибок ключей) в `docs/ARCHITECTURE.md` §8 не проверена
  на живом сервисе. У этого API нет ни маски ключа, ни расхода по ключам.
- Живая проверка с настоящим NanoGPT (`npm run test:live`, нужен `NANOVIA_LIVE_KEY`) покрывает запрос, стриминг, баланс и
  подписку; Management API и подписочный путь оплаты на настоящем сервисе не проверялись.
